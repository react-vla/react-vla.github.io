TL;DR REACT turns flow-based VLA action chunking into rolling denoising: future action blocks are refined under several fresh observations before they are executed, so the robot reacts quickly without giving up smooth, long-horizon motion. Dual Decoupling then streams actions at camera rate on a single GPU.

Abstract

Flow-based vision-language-action (VLA) models generate action chunks for temporally coherent robot motion, but chunked control creates a fundamental closed-loop trade-off: long chunks provide smooth execution, whereas frequent replanning improves reactivity at the cost of action discontinuities. We introduce REACT, a rolling-denoising framework that makes flow-based VLAs more reactive while preserving long-horizon context. Instead of regenerating entire action chunks from scratch, REACT maintains a persistent action buffer with staggered flow timesteps. At each control step, the full horizon is denoised using the latest observation, the cleanest action block is executed, partially refined future blocks are shifted forward, and fresh noise is appended to the tail. As a result, each executed action block is refined across multiple recent observations before deployment. To support real-time control, we further introduce dual decoupling, which separates sensing, VLM encoding, DiT denoising, and action execution, enabling high-frequency observation updates and action streaming under practical compute constraints. Across the RoboTwin 2.0 simulation benchmark and real-world tasks spanning bimanual manipulation and dynamic control on multiple robot platforms, REACT improves task success and reduces reaction latency while producing smoother trajectories than frequent-replanning and asynchronous baselines.

Why chunked VLAs react slowly

Action chunking made flow-based VLAs smooth and reliable, but it also decides how often the policy can look at the world. We make that rate explicit and show why neither faster inference nor shorter chunks fixes it.

1

Action chunking: coherent, but open-loop inside a chunk

Predicting a chunk of \(H\) future actions from one observation improves temporal consistency, reduces compounding errors and keeps a multimodal policy committed to a single coherent motion mode.

The price is that the robot executes the first \(H_e\) actions of the chunk open-loop. If the goal moves while the chunk is running, the rest of the chunk was planned for a scene that no longer exists, and the robot keeps executing these stale-context actions until the next chunk is predicted.

2

Reactivity is input throughput, not control frequency

We separate two rates. Input throughput \(\Phi_{\text{in}}\) is how often a fresh observation actually enters action generation; output throughput \(\Phi_{\text{out}}\) is how many executable actions are produced per second:

\[\Phi_{\text{in}} = \frac{1}{T_{\text{cycle}}}, \qquad \Phi_{\text{out}} = \frac{H_e}{T_{\text{cycle}}},\]

where \(T_{\text{cycle}}\) is the interval between two inference cycles that consume the latest observation.

The control frequency only tells you how often commands are sent. A synchronous \(\pi_{0.5}\) with \(H_e{=}50\) streams actions at 28.8 Hz, yet it looks at the scene only 0.58 times per second. Reaction to a sudden change is bounded by \(\Phi_{\text{in}}\), which is why we use it as the measure of reactivity.

3

Faster or asynchronous inference is not enough

Executing the chunk, not computing it, dominates the cycle:

\[T^{\text{sync}}_{\text{cycle}} = T_{\text{infer}} + \frac{H_e}{f_{\text{ctrl}}}, \qquad T^{\text{async}}_{\text{cycle}} = \max\!\Big(T_{\text{infer}},\ \frac{H_e}{f_{\text{ctrl}}}\Big).\]

Halving inference time therefore lifts \(\Phi_{\text{in}}\) only from 0.58 to 0.59 Hz. Asynchronous inference hides latency, but still consumes one observation per chunk (0.60 Hz). Async+RTC also stitches chunks predicted from different observations: it has the highest simulation jerk of all methods (2022.2) and only 17.7% real-world success.

4

Shorter execution horizons trade coherence for freshness

The naive fix is to replan more often. Going from \(H_e{=}50\) to \(H_e{=}5\) raises \(\Phi_{\text{in}}\) from 0.58 to 4.28 Hz, but it introduces two failure modes:

More chunk boundaries, more discontinuities

Each new chunk is sampled independently from a multimodal policy, so consecutive chunks need not agree where they meet. Every replanning step adds a boundary where the trajectory can jump or switch to a different motion mode; the more often the policy replans, the more of these inconsistent transitions the robot executes.

Stopping before a state change completes

A short chunk can end before the scene actually changes. The next observation looks almost the same, so the policy re-enters the same approach or gets trapped in out-of-distribution contact states: \(\pi_{0.5}\) H50E10 scores 0% on Bottle Cap Unscrewing on both robots.

REACT is built to get both: the observation freshness of short chunks and the long-horizon coherence of full chunks.

Overview

Method

1 · Rolling denoising

REACT keeps a persistent buffer of \(H = KS\) actions, split into \(K\) blocks of length \(S\) (\(K{=}5\), \(S{=}10\), \(H{=}50\)). Instead of one flow time for the whole horizon, every position gets a staircase time, so the front block is nearly clean and the tail is pure noise:

\[\tau_j = \frac{\lfloor j/S \rfloor + 1}{K}, \qquad j = 0,\dots,H-1.\]

Each control update runs one DiT pass under the newest observation \(\mathbf{o}_i\) and advances every block by one stage, then executes the clean front block, shifts, and appends fresh noise:

\[\widetilde{\mathbf{x}}^{(i)} = \mathbf{x}^{(i)} - \tfrac{1}{K}\, v_\theta\big(\mathbf{x}^{(i)}, \boldsymbol{\tau}, \mathbf{o}_i\big), \qquad \mathbf{x}^{(i+1)} = \big[\widetilde{B}_1, \dots, \widetilde{B}_{K-1}, \boldsymbol{\epsilon}_{\text{new}}\big].\]

Every executed block has been refined under \(K\) consecutive observations, while adjacent blocks are always denoised together in one 50-action context, which keeps them in the same motion mode.

2 · Dual Decoupling

Run serially, rolling denoising would still wait for VLM encoding, DiT denoising and execution before using the next observation. Dual Decoupling is an inference-time scheduler that splits the loop into independent streams and leaves the model weights unchanged:

  • Sensing selects one camera frame every \(S\) periods, without waiting for execution.
  • VLM pool: \(M\) workers encode selected frames into a latest-ready embedding cache.
  • DiT consumes the freshest embedding with the rolling buffer and commits the next \(S\) actions.

As long as the worker pool keeps up with the selected stream,

\[\Phi^{\text{REACT}}_{\text{in}} = \min\!\Big(\frac{f_{\text{cam}}}{S},\ \frac{1}{T_{\text{DiT}}}\Big), \qquad \Phi^{\text{REACT}}_{\text{out}} = \min\!\Big(f_{\text{cam}},\ \frac{S}{T_{\text{DiT}}}\Big).\]

With \(S{=}10\) and \(M{=}2\) workers on one RTX 4090, REACT consumes observations at 3 Hz and streams actions at 30 Hz. The embedding is on average 233 ms old (p95 383 ms, max 416 ms) against a 333 ms observation period, so conditioning is never more than one selected observation behind.

Training: staircase flow matching

Rolling inference queries the action expert at a fixed set of per-block noise levels. REACT trains on exactly those levels, which also turns out to make training faster.

Standard flow matching

One continuous timestep is sampled per training chunk and shared by all \(H\) actions (for \(\pi_{0.5}\), \(\tau \sim \mathrm{Beta}(1.5, 1)\)). Covering the whole path from noise to clean actions takes many samples, and the model is never trained on the mixed noise levels that rolling inference uses.

Staircase training (REACT)

Each block \(B_k\) is noised to its fixed level \(\tau = (k{+}1)/K\), \(\mathbf{x}_{\tau_j} = \tau_j\boldsymbol{\epsilon} + (1-\tau_j)\mathbf{a}\), and one forward pass supervises all \(K\) denoising stages:

\[\mathcal{L}_{\text{REACT}} = \frac{1}{K}\sum_{k=0}^{K-1} \frac{1}{SD}\sum_{j\in B_k} \big\| v_\theta^{(j)} - u^{(j)}_{\tau_j} \big\|^2 .\]

Training efficiency

On Click Bell, Move Playing Card Away and Press Stapler, REACT reaches 52.7% average success after 3k steps (\(\pi_{0.5}\): 25.0%) and matches \(\pi_{0.5}\)'s 30k-step performance with only 15k steps. On the out-of-distribution demo_randomized data, average open-loop MSE drops from 0.272 to 0.048.

Dynamic tasks

Two specialized tasks isolate the two requirements of dynamic control: reacting to continuously changing physical states, and reacting to sudden visual events.

Pour Rice · ARX X5

The robot must stop pouring once the rice reaches the target mark. Long open-loop chunks react late and over-pour; REACT's closed-loop refinement stops at the mark far more often (63% vs. 3% for π0.5 H50E50).

Reaction Game · Franka R3

The robot must press a key as soon as the on-screen signal turns green, directly measuring visual-to-motor latency. A single timing script drives both the stimulus and the readout; the human reference teleoperates the same arm through the same timing path.

Full REACT has the lowest mean robot latency, 29 ms above human teleoperation of the same arm and about 2× faster than full-chunk π0.5.
